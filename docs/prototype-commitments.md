# الالتزامات الوظيفية

## التزامات تم تنفيذها

- تطبيق React أحادي الصفحة بمسارات نظيفة (`/ar/about`، `/ar/cases/patchouli`) مع طبقة توافق تحوّل روابط النسخة الأولى (`case.html?id=`) تلقائيًا.
- نظام تصميم مشترك عبر طبقات `assets/css/` (`site`, `folio`, `round2`–`round4`, `hero-live`).
- prerender بعد البناء يكتب ملف HTML ثابتًا لكل مسار قابل للأرشفة (36 ملفًا = 18 مسارًا × لغتان) بالعنوان والوصف و`canonical` و`hreflang` وOpen Graph وJSON-LD الصحيحة — عبر `scripts/prerender.mjs`.
- بوابة نشر (`npm run check:release`) تمنع النشر العام بينما أسماء العملاء وأرقامهم بلا اعتماد صريح. `EM_RELEASE_APPROVED=1` مكوّن الآن في `.env.production` للمنتج النهائي.
- اعتماد ملف Website Design كمرجع تنفيذي أساسي.
- دعم العربية والإنجليزية فعليًا، مع `lang` و`dir`.
- تنقل علوي إلى: الرئيسية، من نحن، الاستشارات، التنفيذ، القطاعات، قصص النجاح، الرؤى، التواصل.
- `Book a Consultation` كالمسار الأساسي في الرأس والتذييل.
- مسار `Send an Inquiry` مختلف الحقول على صفحة التواصل.
- قائمة هاتف كاملة الشاشة مع قفل التمرير وEscape وإدارة التركيز.
- فهرس استشارات ثابت على سطح المكتب وaccordion على الهاتف.
- عرض الهدف والنطاق والأثر ومؤشرات القياس للحلول التنفيذية.
- عرض القطاعات الستة مع لوحة سياق لوحة المفاتيح.
- عرض قصص النجاح الخمس وصفحات تفصيل `/ar/cases/:id`.
- مكتبة الرؤى الخمس مع صفحة تفصيل مستقلة لكل مادة `/ar/insights/:id`.
- نموذج تأهيل يجمع حقول `website-architecture.md`: الاسم، البريد، الشركة، الهاتف، الرسالة.
  الحقول المطلوبة: الاسم، البريد، الرسالة. الحقول الاختيارية: الشركة، الهاتف.
- عدم مسح النموذج بعد نجاح الإرسال.
- دعم `:focus-visible` و`prefers-reduced-motion`.

## سلوك النموذج

### قبل الإرسال

- يمكن للمستخدم التنقل بين الحقول طبيعيًا.
- الحقول المطلوبة لا تُقفل مسبقًا.
- لا يتم مسح البيانات عند وجود خطأ.

### عند وجود أخطاء

- تظهر رسالة بجانب كل حقل ناقص.
- يتم تحديد الحقل غير الصالح بـ `aria-invalid` و`aria-describedby`.
- يُنقل التركيز إلى أول حقل غير صالح.
- لا تعرض الصفحة رسالة نجاح كاذبة.

### عند النجاح

- تظهر رسالة تأكيد داخل الصفحة (`role="status"`).
- توضح أن الإرسال تم عبر FormSubmit وسيتم المتابعة يدويًا.
- لا يُفرغ النموذج حتى لا يُفقد السياق أثناء المراجعة.

## حدود prototype الحالية

- نموذج الاستفسار يرسل عبر FormSubmit AJAX إلى صندوق الاستقبال المكوّن، مع متابعة يدوية من الفريق.
- لا يوجد backend أو API أو CRM مملوك داخل هذا المستودع؛ FormSubmit هو ناقل خارجي مُدار من المالك.
- لا يوجد تقويم فعلي لحجز موعد أو اختيار أوقات؛ الاستشارة تبدأ باستفسار وتُتابع يدويًا.
- لا توجد صور تحريرية معتمدة بعد؛ تُترك مساحة تصوير مع تعليق واضح.
- النتائج والأرقام تحتاج اعتمادًا تجاريًا وقانونيًا قبل النشر.
- الرؤى الحالية نماذج محتوى وليست مقالات منشورة كاملة.
- التطبيق يبني 36 صفحة ثابتة عبر React renderToString + StaticRouter في Node.js، بدون متصفح.
- فلترة الرؤى بحسب الموضوع غير منفّذة: المواد الخمس الحالية لكلٍّ منها موضوع مختلف، فالفلتر سيعرض مادة واحدة لكل خيار. يُعاد النظر فيها حين تتكرر المواضيع.

## متطلبات ما قبل الإنتاج

- اعتماد الشعار كملف أصلي SVG/PNG عالي الدقة.
- اعتماد الصور والأسماء والأرقام وقصص النجاح.
- تحديد الدول والأسواق المستهدفة بدقة.
- تفعيل مستلم FormSubmit والتحقق من وصول الرسائل، أو اعتماد ناقل بريد/CRM بديل بقرار من المالك.
- تحديد إطار المتابعة اليدوية للاستفسارات؛ لا يوجد مسار حجز أو اختيار أوقات في النسخة الحالية.
- إضافة سياسة الخصوصية والموافقة على التواصل.
- مراجعة النص العربي والإنجليزي تحريرياً.
